# Corporate Mortal Kombat — design

Пародийная браузерная игра. Вместо драки с Шао Каном игрок делает карьеру в
корпорации Внешнего Мира: от стажёра до заместителя Шао Кана по стратегическому
развитию. Некоммерческий проект «поржать» по мотивам поста в Telegram.

## Цели

- Качественно проработанная 2D-игра: визуальная новелла между боями,
  кинематографичные пошаговые «бои-переговоры» в интерфейсе Mortal Kombat.
- Единый визуальный стиль: фотореализм как на референсе
  `assets/reference/post-hero-and-shao-kahn.png` — суровые воины Outworld в
  типовом офисе с черепами. Контраст «пафос против офисной рутины» и есть шутка.
- 15–20 минут прохождения, три концовки.
- Результат сборки — статика, деплоится на GitHub Pages.
- Контент и ассеты отделены от движка: новая ступень добавляется файлом данных
  и набором картинок, движок не трогается.

## Не входит

Сохранения прогресса (кроме настройки звука), мобильная раскладка, локализация,
случайная генерация событий, покадровые спрайтшиты, мультиплеер.

## Стек

- **Vite + TypeScript**, строгий режим. Сборка `vite build` в `dist/`.
- **PixiJS 8** — рендер экрана боя: сценограф, спрайты, контейнеры-слои,
  тикер, авто-dpr. `ColorMatrixFilter` из ядра для серого экрана,
  `GlowFilter` из пакета `pixi-filters` для баннеров — единственная
  дополнительная зависимость рендера.
- **GSAP** — твины и таймлайны хореографии боя.
- **Vitest** — тесты чистой логики и данных.
- Экраны старта, событий, результата и концовок — HTML/CSS, без Pixi.
- Зависимости ставятся `npm install --ignore-scripts`; версии зафиксированы
  в `package-lock.json`. Новые пакеты добавляются только по необходимости и
  с проверкой, что у них нет install-скриптов.
- Генерация ассетов: OpenRouter Image API (`POST /api/v1/images`),
  основная модель `bytedance-seed/seedream-5-0-pro` (до 14 референсов,
  разрешение 1K/2K, произвольный `aspect_ratio`), запасная
  `google/gemini-3-pro-image`. Модель — поле в манифесте. Скрипт генерации на
  Node (`tsx`), постобработка на Python 3 + Pillow + NumPy.
- Ключ в `.env` в корне: `OPENROUTER_API_KEY=...`. Файл в `.gitignore`.
- Язык интерфейса и контента — русский. Баннеры в бою — английские, как в
  оригинале (`FIGHT!`, `FLAWLESS PRESENTATION`).

## Экраны и движок

`engine.ts` хранит `state` и текущий экран. Каждый экран реализует
`{ mount(root: HTMLElement, ctx: Ctx): Promise<void>; unmount(): void }`,
где `ctx = { getState, setState, content, assets, audio, go }`. Переход
`go(name)` вызывает `unmount` старого, ждёт `mount` нового (бой инициализирует
Pixi асинхронно). Никакой игровой логики в `engine.ts` нет, только
маршрутизация и владение состоянием. Данные между экранами передаются только
через `GameState`.

```
start → event ⇄ battle → event | ending
                            ↓
                     restart → start
```

Экрана «результат» в роутере нет: панель исхода — часть экрана боя, она
появляется в оверлее поверх канваса, когда отыгран баннер, и её кнопка
«Дальше» вызывает `go('event')` или `go('ending')`.

- **start** — титульный арт (герой и Шао Кан пожимают руки), логотип
  «CORPORATE MORTAL KOMBAT» в стиле драконьей эмблемы с офисным зажимом для
  бумаг, прогресс загрузки группы `core` + `rank0`, кнопка «Начать карьеру».
  Первый клик разблокирует Web Audio.
- **event** — фон локации на весь экран, портрет собеседника справа, диалоговое
  окно снизу с печатанием (клик — показать целиком), карточки выбора появляются
  только когда печатание завершено. Хоткеи 1–4. Сверху HUD.
- **battle** — контейнер с `aspect-ratio: 16/9` и letterbox; внутри канвас
  Pixi (логические 1280×720) и DOM-оверлей тех же размеров. На канвасе: фон,
  спрайты, партиклы, полоски, таймер, баннеры, виньетка. В оверлее: карточки
  приёмов с тултипом, кнопка mute, панель результата. Координаты мыши на
  канвасе не нужны.
- **ending** — иллюстрация, заголовок, текст, кнопка «Начать карьеру заново».
  Концовка может нести необязательный `epilogue?: { name: string; portrait:
  string; text: string }` — карточку с портретом и репликой под основным
  текстом — и необязательные `variants?: { requiresFlag: string; title?:
  string; text?: string; epilogue?: … }[]`: экран берёт первый вариант, чей
  флаг стоит, и он перекрывает заголовок/текст/эпилог базовой концовки.

HUD (событие и панель результата): должность, неделя, четыре стата
полосками с анимацией и всплывающими `+10`/`−5`.

## Состояние игры

```ts
interface GameState {
  rank: number;              // 0..5
  step: number;              // индекс события; step === events.length → бой
  week: number;
  stats: Stats;              // loyalty, reputation, competence, stress: 0..100
  flags: Set<string>;
  seenEvents: Set<string>;   // источник признака «повтор события»
  lastBattle: { bossId: string; outcome: 'win' | 'lose' | 'fatality' } | null;
}
```

Начальные статы: Лояльность 30, Репутация 20, Компетентность 30, Стресс 10.
`createInitialState()` — единственный источник старта; «Начать карьеру заново»
вызывает её же.

Правила продвижения (`state.ts`):

- `currentEvent(state, ranks)` возвращает событие по `step` или `null`, если
  `step >= events.length` — тогда очередь боя. У ступени 5 `events: []`, бой
  начинается сразу.
- `applyChoice(state, event, choice)`: `setFlag` ставится всегда; из `effects`
  при повторе события (`seenEvents.has(event.id)`) применяется только
  `stress`; событие добавляется в `seenEvents`; `step += 1`; `week += 1`.
- `afterBattle(state, boss, outcome)`: записывает `lastBattle`. Победа —
  `stress −10`, если босс не финальный `rank += 1`, `step = 0`; поражение —
  `stress +25`, `step = 0`, ранг не меняется; fatality — статы и ранг не
  меняются. `week += 1` во всех случаях.
- `checkEnding(state, ranks)` возвращает `'burnout'`, если `stress >= 100`;
  `'fatality'`, если `lastBattle?.outcome === 'fatality'`; `'promotion'`, если
  `lastBattle?.outcome === 'win'` и босс с `lastBattle.bossId` финальный;
  иначе `null`. Вызывается экраном события после выбора и экраном боя после
  `afterBattle`. `applyChoice` сбрасывает `lastBattle` в `null`. Внутри
  `applyChoice` и `resolveTurn` концовки не проверяются.

## Статы

- **Лояльность** — усиливает «Согласиться».
- **Репутация** — усиливает «Перевести стрелки» и «Пошутить».
- **Компетентность** — усиливает «Сослаться на данные».
- **Стресс** — растёт от неудач и поражений, штрафует «Пошутить», усиливает
  атаку босса. 100 = концовка «Выгорание».

## События

```ts
interface GameEvent {
  id: string; title: string;
  speaker: { name: string; portrait: string };
  text: string;
  repeatText?: string;              // при повторе ступени, если есть смысл
  choices: Choice[];                // 2..4
}
interface Choice {
  text: string;
  effects?: Partial<Stats>;
  setFlag?: string;
  requiresFlag?: string;
  reaction?: { portrait: string; text: string };
}
```

Вариант с `requiresFlag` виден только при наличии флага; `requiresNotFlag`
нет. Первый вариант события всегда без `requiresFlag`. Если у выбора есть
`reaction`, портрет меняется, печатается ответ, затем кнопка «Дальше».
Текст события перед боем содержит намёк на слабость босса.

## Боевая механика

```ts
interface BattleState {
  confidence: number; maxConfidence: number;   // игрок, старт 100
  patience: number; maxPatience: number;       // босс
  turn: number;
  hitImmune: boolean;        // был удар по иммунитету
  bossSpecialHit: boolean;   // босс провёл спецприём
  finishHim: boolean;        // patience < 15% у финального босса
}
interface TurnResult {
  battle: BattleState;
  outcome: 'continue' | 'win' | 'lose' | 'fatality';
  player: { move: MoveId; damage: number; weakness: boolean; immune: boolean; lineIndex: number };
  boss: { damage: number; special: boolean; lineIndex: number } | null;
}
```

`createBattle(boss)` заполняет `BattleState`. `availableMoves(boss, battle)`
возвращает `{ move, enabled }[]`: четыре базовых приёма всегда включены,
`strike` присутствует только у финального босса и включён только при
`battle.finishHim`. `resolveTurn(battle, move, stats, boss, rng =
Math.random)`: приём `strike` допустим только когда `availableMoves` его
включает, иначе бросает ошибку; допустимый `strike` → `outcome: 'fatality'`,
`boss: null`. Иначе урон игрока; если `patience ≤ 0` → `'win'`, босс не
отвечает. Иначе ответ босса; если `confidence ≤ 0` → `'lose'`, иначе
`'continue'`. `lineIndex` для реплик выбирается через `rng`, чтобы контроллер
не тянул случайность сам. Все функции боя принимают `rng` последним
аргументом; тесты передают константы.

| Приём | id | Стат |
|-------|----|------|
| Согласиться | agree | Лояльность |
| Сослаться на данные | data | Компетентность |
| Перевести стрелки | blame | Репутация |
| Пошутить | joke | Репутация, штраф от Стресса |
| Ударить | strike | только финальный босс |

Урон приёма: `10 + stat × 0.15`; «Пошутить» — `10 + reputation × 0.15 −
stress × 0.05`, не ниже 3. Множитель 2 при `weakness`, 0.25 при `immunity`.
Округление до целого. Босс снимает `attack + stress × 0.05`, с шансом 25%
(`rng() < 0.25`) спецприём ×1.5.

Ориентир при стате 30: нейтральный удар 15, по слабости 29. Терпение 120
падает за 5 ходов по слабости и 8 нейтрально, игрок держится около 7 ходов.
Ожидаемый урон босса за ход с учётом спецприёма: `1.125 × (attack + stress ×
0.05)`; игрок переживает `T − 1` ответов, где `T = ceil(patience / урон)`.
Поглощённый за бой урон должен укладываться в 60–90 из 100. Таблица ниже
уточняется симуляцией на этапе 8.

| Босс | Терпение | Атака | Слабость | Иммунитет |
|------|----------|-------|----------|-----------|
| Милина | 90 | 10 | joke | blame |
| Барака | 110 | 11 | agree | joke |
| Китана | 140 | 12 | data | agree |
| Синдел | 170 | 13 | blame | joke |
| Шанг Цунг | 185 | 13 | data | blame |
| Шао Кан | 190 | 15 | agree | data |

Шао Кан: атака 15 по симуляции и плейтесту этапа 8 (см. README, раздел «Баланс»).

```ts
interface Boss {
  id: string; name: string; title: string;
  patience: number; attack: number;
  weakness: MoveId; immunity: MoveId; final: boolean;
  sprites: { idle: string; attack: string; hurt: string; defeated: string };
  portraits: { neutral: string; angry: string };
  intro: string;
  lines: { hit: string[]; immune: string[]; special: string[]; defeated: string[] };
}
```

Исход:

- **Победа**: `FLAWLESS PRESENTATION`, если `!hitImmune && !bossSpecialHit`,
  иначе `PROMOTION!!!`.
- **Поражение**: `PERFORMANCE REVIEW`. Ступень повторяется с события 0.
  Проиграть игру можно только через Выгорание.
- **Fatality**: только у финального босса. Карточка «Ударить» видна с начала
  боя, но задизейблена с подсказкой «Не при свидетелях», пока `finishHim`
  ложен. После баннера `FINISH HIM` включается. Нажатие → концовка.

## Хореография боя

`choreo.ts` превращает `TurnResult` в список шагов:

```ts
type HeroPose = 'idle' | 'attack' | 'hurt' | 'win';
type BossPose = 'idle' | 'attack' | 'hurt' | 'defeated';
type Step =
  | { t: 'pose'; who: 'hero'; pose: HeroPose }
  | { t: 'pose'; who: 'boss'; pose: BossPose }
  | { t: 'move'; who: 'hero' | 'boss'; dx: number; ms: number }   // dx относительно базовой позиции, 0 = вернуться
  | { t: 'camera'; zoom: number; ms: number }                      // 1 = вернуться
  | { t: 'flash'; ms: number; color: string }
  | { t: 'shake'; ms: number; amp: number }
  | { t: 'particles'; at: 'hero' | 'boss' | 'screen'; kind: 'paper' | 'sparks' | 'confetti' }
  | { t: 'damage'; at: 'hero' | 'boss'; value: number; muted: boolean }
  | { t: 'bar'; who: 'hero' | 'boss'; to: number; ms: number }
  | { t: 'line'; text: string; style: 'bubble' | 'center' }
  | { t: 'banner'; text: BannerText }
  | { t: 'sound'; name: SoundName; gain?: number }
  | { t: 'voice'; id: string }                                     // реплика диктора
  | { t: 'dim'; to: number; ms: number }
  | { t: 'grayscale'; to: number; ms: number }
  | { t: 'timeScale'; to: number }
  | { t: 'wait'; ms: number };
```

Шаги идут последовательно; шаг с `ms` ждёт своей длительности, остальные
мгновенные. Каждый ход заканчивается шагами возврата: `move dx: 0`,
`camera zoom: 1`, `pose idle`. `timeScale` действует до следующего
`timeScale` или до конца боя. Это чистые данные, `choreo.test.ts` проверяет их без Pixi:
удар по иммунитету не содержит `flash` и `shake`, спецприём содержит `dim`,
победа содержит `timeScale` 0.5 и баннер, у финального босса при переходе
`finishHim` появляется баннер `FINISH HIM`.

**Ход игрока.** Герой в `attack`, шаг вперёд 80 px за 150 мс, камера
зум 1.08 за 150 мс, вспышка белого 60 мс, босс в `hurt` и отскок 40 px,
партиклы, цифра урона, тряска 200 мс с амплитудой `4 + damage × 0.3`, полоска
Терпения к новому значению за 300 мс с призрачным остатком, реплика босса.
По иммунитету: без вспышки, тряски и партиклов, цифра серая, реплика из
`lines.immune`. Возврат в `idle`.

**Ход босса.** Симметрично, тряска ×1.5. Спецприём: `dim` до 0.4, красная
вспышка, реплика крупно по центру, затем удар.

**Победа.** Босс `defeated`, герой `win`, `timeScale` 0.5, `wait` 1000,
`timeScale` 1, баннер, `particles at: 'screen', kind: 'confetti'`, звук
`win`. **Поражение.** Герой `hurt`, `grayscale` до 1 за 600 мс, баннер, звук
`lose`.

**Баннеры.** `ROUND 1` и `FIGHT!` в начале, исход в конце, `FINISH HIM` при
переходе `finishHim`. Тяжёлый гротеск с металлическим градиентом, появление
масштабом 3→1 за 250 мс с тряской, свечение фильтром.

**Idle.** Дыхание: масштаб по Y ±1.5% с периодом 2 с через GSAP на
повторе. Фон с параллаксом 3% от смещения камеры.

## Контроллер боя

`screens/battle.ts` держит фазу
`'intro' | 'awaitInput' | 'playerAnim' | 'bossAnim' | 'over'`. Карточки
приёмов активны только в `awaitInput`; вход в `resolveTurn` защищён проверкой
фазы, а не состоянием кнопок. Хоткеи 1–5. Контроллер берёт `TurnResult`,
получает шаги из `choreo`, исполняет их по очереди: шаги рендера уходят в
`scene`/`effects`, `sound` и `voice` — в `audio`, `wait` —
`gsap.delayedCall`, поэтому slow-mo замедляет и паузы, это намеренно. После
последнего шага фаза `awaitInput` или `over`; в `over` контроллер вызывает
`afterBattle`, `checkEnding` и показывает панель результата в оверлее.

## Рендер

`scene.ts` создаёт `Pixi.Application` один раз за сессию (ленивый
синглтон, `await app.init({ resizeTo: container, autoDensity: true,
resolution: devicePixelRatio })`) и при монтировании боя вставляет его канвас
в контейнер. При `unmount` канвас извлекается из DOM, сцена очищается,
активные твины убиваются (`gsap.killTweensOf` по сцене), текстуры не
уничтожаются — они принадлежат `assets.ts`. Логическая сцена 1280×720 живёт
в корневом контейнере с `scale = min(w / 1280, h / 720)` и центрированием;
пересчёт на событии `resize` приложения. DOM-оверлей — абсолютно
позиционированный элемент того же родителя с `aspect-ratio: 16/9`, его
раскладка в процентах, поэтому отдельного масштабирования ему не нужно.

Слои: `background`, `shadows`, `fighters`, `fx`, `hud`, `banners`,
`vignette`. Тикера два и это осознанно: Pixi рисует, GSAP анимирует свойства
объектов сцены и сам гонит свой rAF. `timeScale` применяется к
`gsap.globalTimeline.timeScale`, при `unmount` возвращается 1.

Спрайты бойцов рисуются от якоря (точка ног из манифеста), поэтому смена
позы не двигает персонажа. Герой смотрит вправо, боссы влево.

Полоски: заливка, призрачный остаток, который догоняет за 600 мс, имя и
должность под полоской, портрет у внешнего края. Таймер декоративный, тикает
от 99 и останавливается на 0.

## Звук

Звуковые эффекты `audio.ts` синтезирует через Web Audio, файлов для них
нет:

- `hit` — шумовой удар с низкой синусоидой, громкость от урона.
- `immune` — глухой короткий «бум».
- `special` — низкий гул и щелчок.
- `whoosh` — фильтрованный шум при шаге.
- `bar` — тик уменьшения полоски.
- `banner` — гонг: синус с быстрым спадом, feedback-delay и lowpass.
- `type` — тихий клик на буквах печатания.
- `win` — трёхнотный фанфар, `lose` — нисходящий тон.

**Музыка** генерируется заранее через OpenRouter, модель
`google/lyria-3-clip-preview` (30-секундные клипы), хранится в
`assets/audio/*.mp3` и зациклена с кроссфейдом 1 с через Web Audio:

| id | Где | Настроение |
|----|-----|------------|
| `mu_title` | титул | пафосный оркестровый MK-мотив с офисным телефоном в ритме |
| `mu_office` | события ступеней 0–2 | лёгкий лаунж с тревожными низами |
| `mu_council` | события ступеней 3–4 | мрачный корпоративный эмбиент |
| `mu_battle` | бои 0–4 | индустриальный техно-бит в духе MK |
| `mu_final` | финальный бой | тяжёлый хор и барабаны |
| `mu_ending` | концовки | короткий торжественный стингер |

**Диктор** — заранее сгенерированные реплики через `openai/gpt-audio`
(низкий мужской голос, инструкция «голос диктора Mortal Kombat»):
`ROUND 1`, `FIGHT!`, `FLAWLESS PRESENTATION`, `PROMOTION`,
`PERFORMANCE REVIEW`, `FINISH HIM`, `FATALITY`, `CORPORATE MORTAL KOMBAT`.
Файлы `assets/audio/vo_*.mp3`, играют вместе с баннером. Если файл не
загрузился — баннер молча.

Аудиозаписи лежат в том же манифесте с `kind: "music" | "voice"`, полями
`prompt`, `model`, `duration` (секунды) и `group`; поля `size`, `anchor`,
`chroma`, `flip`, `references` для них отсутствуют. Группы: `mu_title` и все
`vo_*` — `core`; `mu_office`, `mu_battle` — `rank0`; `mu_council` — `rank3`;
`mu_final` — `rank5`; `mu_ending` — `endings`. `gen-assets.ts` ведёт для них
отдельный проход: `POST /api/v1/chat/completions` с `stream: true`,
`modalities: ["text", "audio"]`, `audio: { voice, format }`; аудио-вывод
доступен только в стриме, base64-чанки из `choices[0].delta.audio.data`
склеиваются и сохраняются. Запрашивается `format: "mp3"`; если модель отдаёт
только wav/pcm16, файл конвертируется в mp3 через `ffmpeg` (есть на машине
разработчика). `audio.ts` декодирует файлы в `AudioBuffer`, музыку зацикливает
двумя источниками с кроссфейдом 1 с. Бюджет: 6 клипов по 0.04 $, диктор
тарифицируется по токенам, ориентир до 0.1 $ на все реплики.

Кнопка mute в HUD и оверлее боя, состояние в `localStorage` под ключом
`cmk.muted`.

## Ассеты

```json
{
  "id": "sp_baraka_idle",
  "kind": "sprite",
  "group": "rank1",
  "character": "baraka",
  "file": "assets/img/sprites/baraka_idle.webp",
  "size": [700, 900],
  "anchor": [350, 880],
  "model": "bytedance-seed/seedream-5-0-pro",
  "prompt": "...",
  "references": ["assets/reference/post-hero-and-shao-kahn.png", "pt_baraka_neutral"],
  "dependsOn": ["pt_baraka_neutral"],
  "chroma": "#FF00FF",
  "flip": false,
  "generated": false
}
```

`kind`: `sprite | portrait | background | illustration | music | voice`.
`group`: `core`
(герой, титул, UI), `rank0..rank5`, `endings`. `references` — пути к файлам
или id других записей; для id подставляется сырой `assets/raw/<id>.png`
(до вырезания фона), а не WebP с альфой. `dependsOn` перечисляет id, которые
должны быть сгенерированы раньше.

| Тип | Штук | Размер | Описание |
|-----|------|--------|----------|
| Герой, спрайты | 4 | 700×900 | idle, attack, hurt, win |
| Герой, портреты | 2 | 512×512 | neutral, worried |
| Боссы, спрайты | 24 | 700×900 | idle, attack, hurt, defeated |
| Боссы, портреты | 12 | 512×512 | neutral, angry |
| Второстепенные портреты | 2 | 512×512 | Рептилия (IT-поддержка), Джакс (охрана) |
| Фоны локаций | 6 | 1600×900 | по одному на ступень |
| Иллюстрации | 4 | 1600×900 | титул и три концовки |

| Музыка | 6 | 30 с, mp3 | см. раздел «Звук» |
| Диктор | 8 | 1–2 с, mp3 | см. раздел «Звук» |

Итого 54 картинки и 14 аудиофайлов. Бюджет веса на файл: спрайт ≤ 150 КБ,
портрет ≤ 80 КБ, фон и иллюстрация ≤ 300 КБ, музыкальный клип ≤ 400 КБ,
реплика ≤ 40 КБ. Потолок суммы: 28 × 150 + 16 × 80 + 10 × 300 + 6 × 400 +
8 × 40 = 11 200 КБ, тест проверяет сумму ≤ 11.5 МБ. На титуле грузятся
только `core` и `rank0` — около 3 МБ. WebP качество 72 для фонов, 80 для
спрайтов, mp3 96 кбит/с. Стоимость: Seedream 5.0 Pro
0.045 $ за картинку в 1K и 0.09 $ в 2K, плюс 0.003 $ за референс. Первый
проход: 10 фонов и иллюстраций в 2K (0.90 $), 44 спрайта и портрета в 1K
(1.98 $), референсы около 0.30 $, музыка 0.24 $, диктор до 0.10 $ — около
3.5 $. Пересъём половины картинок добавляет ещё около 1.7 $; укладываемся в
10 $ на счёте.

**Единство стиля.** Общий префикс стиля в каждом промпте (фотореалистичный
кинематографичный кадр, мягкий офисный свет, приглушённые тёплые тона,
детализация как на референсе) плюс референс из поста. Якорь личности
персонажа: сначала нейтральный портрет (референс: стиль), затем `idle`
(референсы: стиль + портрет), затем `attack`, `hurt`, `defeated` (референсы:
стиль + портрет + `idle`). Это выражено через `dependsOn`, генератор делает
топологическую сортировку и падает при цикле. Поле `seed` даёт
воспроизводимость перезапуска, не консистентность между позами.

**Спрайты** запрашиваются в полный рост на однородной мадженте `#FF00FF`
(в палитре персонажей её нет; у Рептилии зелёный костюм), ракурс три четверти,
свет слева. `postprocess.py` обрабатывает четыре позы персонажа **вместе**:
маска по расстоянию в YCbCr до ключевого цвета с мягкой кромкой, despill
(ключевой канал сжимается к среднему двух других), общий bounding box по
всем позам, единый паддинг, одинаковый холст 700×900, якорь ног пишется в
манифест. Так смена позы не двигает персонажа. `flip` зеркалит при
неправильном направлении взгляда.

**Пайплайн.** `npx tsx tools/gen-assets.ts [--only id] [--group name]
[--force]` сортирует манифест по `dependsOn`, пропускает записи с
`generated: true`, для остальных шлёт запрос: `model`, `prompt`,
`aspect_ratio` из `size`, `resolution: "2K"` для фонов и `"1K"` для
остального, референсы как data-URL в `input_references`
(`{ type: "image_url", image_url: { url } }`). Картинка из `data[0].b64_json`
сохраняется в `assets/raw/<id>.png` (локально, в `.gitignore`), затем
вызывается постобработка для персонажа или одиночной записи, после успеха
`generated: true`. Ошибки сети — 3 повтора с паузой. Пересъём —
`--only id --force`. Матовку можно перекатать по сырым PNG без новой
генерации.

**Загрузка в игре.** `assets.ts` читает манифест, `loadGroup('core')` и
`loadGroup('rank0')` идут на титульном экране с прогрессом; при входе в
события ступени N в фоне идёт `prefetchGroup('rank' + (N + 1))`, группа
`endings` префетчится на ступени 4. Отсутствующая или не сгенерированная
картинка заменяется прямоугольником с id — игра не падает, брак виден.

## Обработка ошибок

`validateContent(ranks, manifest)` на старте: у каждой ступени 2 события и
1 босс (у последней 0 событий); `background` есть у каждой ступени;
`weakness ≠ immunity`; первый вариант события без `requiresFlag`; каждый
`requiresFlag` кем-то ставится; каждый id ассета из контента есть в
манифесте; ровно один босс `final: true`, и он последний. При ошибке —
список на экране, игра не стартует.

Загрузка ассетов: ошибка одной картинки логируется, ставится заглушка.
