# Бой как диалог — дизайн

Дополнение к основной спеке `2026-09-03-corporate-mortal-kombat-design.md` (разделы «Боевая механика», «Хореография боя», «Контроллер боя»). Там, где этот документ противоречит основной спеке, действует этот документ.

## Проблема

Сейчас босс говорит одну реплику в интро, после чего игрок до десяти ходов подряд нажимает абстрактные карточки «Согласиться / Сослаться на данные / Перевести стрелки / Пошутить». Реакции босса берутся случайно из общего списка. Диалога нет: непонятно, на что игрок отвечает и почему босс говорит то, что говорит. Реплики к тому же гасли через 1.6 с (исправлено: пузырь висит до хода игрока, коммит `8c65382`).

## Цель

Каждый ход боя — реплика босса и четыре готовых ответа героя. Карточки внизу — это сами ответы, а не названия тактик. Босс реагирует на конкретный ответ. Формулы урона, баланс, слабости и иммунитеты, симулятор — без изменений: меняется контент и его подача.

## Не входит

- Ветвление: следующая реплика босса не зависит от выбранного ответа (иначе вчетверо больше текста и ломается симуляция баланса).
- Новые тактики, изменения статов, событий, концовок.
- Новый арт и звук. Пятая карточка «Ударить» и FINISH HIM остаются как есть, у карточки появляется текст.

## Понятие «обмен» (exchange)

```ts
export type Tactic = Exclude<MoveId, 'strike'>;            // 'agree' | 'data' | 'blame' | 'joke'
export interface Reply { text: string; reaction: string }   // ответ героя и реакция босса на него
export interface Exchange { prompt: string; replies: Record<Tactic, Reply> }

export interface Boss {
  // …как раньше: id, name, title, patience, attack, weakness, immunity, final, sprites, portraits
  exchanges: Exchange[];                        // ровно 8; exchanges[0] — открывающая реплика (бывший intro)
  strikeText?: string;                          // текст пятой карточки; обязателен у final, запрещён у остальных
  lines: { special: string[]; defeated: string[] };   // hit, immune и intro удалены
}
```

Порядок обменов в бою: 0, 1, 2, 3, 4, 5, 6, 7, затем по кругу 5, 6, 7, 5, … Константа `LOOP_TAIL = 3` в `battle.ts`: после последнего обмена бой возвращается к `exchanges.length - LOOP_TAIL`. Обмены 0–4 — сюжетная дуга босса, 5–7 — «давление», написаны так, чтобы читаться в любом порядке и после любого из соседей. Повторный бой после поражения начинается с обмена 0.

## Изменения в `battle.ts`

```ts
interface BattleState {
  // …как раньше
  exchange: number;   // индекс обмена, чья реплика на экране и чьи ответы лежат на карточках; createBattle → 0
}
interface TurnResult {
  battle: BattleState;
  outcome: 'continue' | 'win' | 'lose' | 'fatality';
  player: { move: MoveId; damage: number; weakness: boolean; immune: boolean; reaction: string };
  boss: { damage: number; special: boolean; lineIndex: number; prompt: string } | null;
}
```

- `reaction = boss.exchanges[battle.exchange].replies[move.id].reaction` (у `strike` — пустая строка, она не показывается).
- `nextExchange(boss, i)`: `i + 1`, если `i + 1 < exchanges.length`, иначе `exchanges.length - LOOP_TAIL`; экспортируется для тестов. `battle.exchange` в результате — уже следующий обмен.
- `prompt = boss.exchanges[next.exchange].prompt` — реплика босса, открывающая следующий ход. Хореография показывает её только при `outcome === 'continue'`.
- `lineIndex` у игрока удалён вместе с вызовом `rng` для него; порядок обращений к `rng` за ход теперь: спецприём → индекс реплики `special`. Тесты `battle.test.ts` пересчитать.
- `lineIndex` у босса остаётся только для `lines.special`; при обычной атаке не используется (0).

## Хореография хода (`choreo.ts`)

Шаг `line` получает режим: `{ t: 'line'; text: string; style: 'bubble' | 'center'; append?: boolean }`. `append: true` дописывает текст новым абзацем в уже висящий пузырь (если пузыря нет — создаёт). Пузырь `bubble` не гаснет сам: его убирает следующий пузырь без `append`, `clearSpeech` в момент хода игрока или `unmount` сцены.

```
intro:        ROUND 1 → wait 900 → line(exchanges[0].prompt) → wait 1400 → FIGHT! → wait 700
ход игрока:   clearSpeech (контроллер) → поза attack → выпад → удар/иммунитет → цифра урона → полоска
              → line(reaction)            ← новый пузырь
              → wait 900                  ← было 500: реакцию надо успеть увидеть до выпада босса
              → возврат героя
ответ босса:  [спецприём: dim → line(special, center) → wait 900 → flash → dim 0]
              → поза attack → выпад → удар по герою → цифра → полоска → wait 400 → возврат босса
              → line(prompt, append)      ← дописывается к реакции; висит, пока игрок думает
победа:       поза defeated → slow-mo → line(defeated[0]) (без append) → баннер → конфетти
поражение:    без реплик, как раньше
FINISH HIM:   как раньше, после append prompt
```

Итог хода на экране: один пузырь «реакция на прошлый ответ + новая реплика», под ним четыре карточки-ответа. Игрок читает без таймера.

## Пузырь (`effects.ts`)

- Пузырь стоит **между бойцами, слева от босса**: правый край на `fighterPoint('boss').x − 60`, нижний край на фиксированной высоте `Y_BUBBLE_BOTTOM = 300` (в координатах сцены 1280×720), растёт вверх при `append`. Ширина переноса 380 px, шрифт 20 px. Так пузырь не закрывает лицо босса и не заезжает на HUD (полоски заканчиваются на ~90 px): при лимитах текста ниже высота ≤ 210 px.
- Маленький «хвостик» треугольником вправо, к боссу.
- `append`: текст дописывается через пустую строку, коробка перерисовывается; короткая анимация появления (alpha 0→1 за 0.2 с) только у нового пузыря, у дописанного — без мигания.
- `center` не меняется.

## Карточки (`screens/battle.ts`, `styles/battle.css`)

```html
<button class="move-card">
  <span class="move-key">1</span>
  <span class="move-text">«Слабых сторон нет: я целиком согласен с политикой компании.»</span>
  <span class="move-meta">Согласиться · ≈17</span>
</button>
```

- Текст ответа — главный, 14–16 px, до трёх строк на 1280 px. Подпись `move-meta` мелкая, серая: название тактики и ожидаемый урон (у «Ударить» — только название). Тултип `title` — прежний `move.hint`.
- Порядок карточек фиксирован и совпадает с клавишами: 1 согласие, 2 данные, 3 стрелки, 4 шутка, 5 удар (только финал).
- Пятая карточка у финального босса показывает `boss.strikeText` и до `finishHim` задизейблена с прежним тултипом.
- `renderMoves()` берёт тексты из `boss.exchanges[battle.exchange]`; вызывается там же, где сейчас (после интро и после каждого хода).
- Тексты вставляются через `textContent`, не `innerHTML` (правило проекта).

## Правила для сценаристов

Объём: 6 боссов × 8 обменов × (1 реплика + 4 ответа + 4 реакции) = 432 реплики плюс `strikeText` у Шао Кана. Существующие `lines.hit` и `lines.immune` — сырьё для реакций: переносить туда, где они подходят к ответу, остальное убрать. `intro` каждого босса — кандидат в `exchanges[0].prompt`. `special` и `defeated` не меняются.

Лимиты (проверяет валидатор): `prompt` ≤ 140 знаков, `reply.text` ≤ 90, `reaction` ≤ 80, ничего пустого.

Содержание:

- Реплика босса — вопрос, требование или выпад, на который естественно отвечать четырьмя способами. Обмены 5–7 не ссылаются на «первый/последний вопрос» и на порядок.
- Четыре ответа узнаются как тактики и без подписи: согласие — лесть/подчинение; данные — цифра, факт, график; стрелки — виноват кто-то другой (конкретный коллега или отдел); шутка — панчлайн. Ответ не может быть смесью двух тактик.
- Реакция на слабость показывает, что босс задет (сбился, записал, отступил); на иммунитет — отмахнулся с презрением, как нынешние `immune`; нейтральная — принял к сведению и двигается дальше. Реакция не называет тактику словами «вы согласились / пошутили», а отвечает по смыслу.
- Герой без пола: в ответах героя нет прошедшего времени от первого лица и прилагательных о себе («я согласен» → «согласие полное», «я сделал» → «сделано»). Герой обращается ко всем боссам на «вы» (в событиях герой никому не «тыкает»; Барака сам говорит герою «ты» — это асимметрия тимлида и джуна, её сохранить).
- Голоса боссов и занятые формулы — по хендофф-заметкам `docs/superpowers/plans/README.md` (разделы «Этап N выполнен»). Сквозные шутки подхватывать, не повторять дословно; ни одна реплика не повторяется у двух боссов.
- Слово «синергия» — только там, где оно уже сюжетно закреплено (Барака запрещает, Шанг Цунг любит, Шао Кан увольняет).
- Ответы не меняют статы и флаги: бой — только урон.
- Шао Кан: `strikeText` — действие героя, одна строка ≤ 60 знаков, в кавычках-«ёлочках» не оформляется (это не реплика).

## Валидатор (`content/schema.ts`)

- `exchanges.length === 8`; у каждого обмена ровно четыре ответа с ключами `agree, data, blame, joke`.
- Лимиты длины и непустота `prompt`, `text`, `reaction`.
- `strikeText` обязателен и непуст при `final`, отсутствует у остальных.
- `lines.special` и `lines.defeated` непусты (как раньше).

## Тесты

- `test/fixtures.ts`: босс с восемью короткими обменами вместо `intro/hit/immune`.
- `test/battle.test.ts`: `reaction` берётся из текущего обмена; `exchange` растёт 0→1→…→7→5→6→7→5; `prompt` — реплика следующего обмена; при `win` `boss === null`; порядок `rng` пересчитан; `strike` даёт `reaction: ''`.
- `test/choreo.test.ts`: интро содержит `exchanges[0].prompt`; ход содержит `line(reaction)` до возврата героя и `line(prompt, append: true)` после атаки босса и только при `continue`; при `lose` шага `append` нет; спецприём — `center` без `append`; победа — `defeated[0]` без `append`.
- `test/content.test.ts`: подсказки слабости/иммунитета ищутся, как раньше, в последнем событии; ссылка на `boss.intro` заменяется на `exchanges[0].prompt`.
- `test/schema.test.ts`: новые ошибки валидатора (7 обменов, лишний ключ ответа, длина 141, `strikeText` у не-финала).
- Симуляция баланса `tools/simulate.ts` и `test/balance.test.ts` — без изменений по смыслу (тексты на урон не влияют).

## Плейтест

Playwright: пузырь после интро висит до хода; после хода виден пузырь «реакция + новая реплика» и карточки с ответами; пузырь не перекрывает HUD и лицо босса на всех шести фонах (скриншот каждого босса с самым длинным обменом); Шао Кан — пятая карточка с `strikeText`; консоль без ошибок. Полное прохождение до повышения.

## Этапы

1. Движок: типы, `battle.ts`, валидатор, фикстуры, тесты; контент боссов временно переведён в новую схему механически (реплика `intro` + по одному ответу-заглушке), чтобы сборка была зелёной.
2. Подача: `effects.ts` (пузырь слева от босса, `append`, хвостик), `choreo.ts`, `screens/battle.ts`, `battle.css`.
3–8. Сценарии: по одному боссу на задачу в порядке ступеней, каждая — со своим ревью текста по правилам выше.
9. Плейтест, скриншоты, README и хендофф-заметки, деплой.
