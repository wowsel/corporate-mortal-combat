# Бой как диалог — дизайн

Дополнение к основной спеке `2026-09-03-corporate-mortal-kombat-design.md` (разделы «Боевая механика», «Хореография боя», «Контроллер боя»). Там, где этот документ противоречит основной спеке, действует этот документ.

## Проблема

Сейчас босс говорит одну реплику в интро, после чего игрок до десяти ходов подряд нажимает абстрактные карточки «Согласиться / Сослаться на данные / Перевести стрелки / Пошутить». Реакции босса берутся случайно из общего списка. Диалога нет: непонятно, на что игрок отвечает и почему босс говорит то, что говорит. Реплики к тому же гасли через 1.6 с (исправлено: пузырь висит до хода игрока, коммит `8c65382`).

## Цель

Каждый ход боя — реплика босса и четыре готовых ответа героя. Карточки внизу — это сами ответы, а не названия тактик. Босс реагирует на конкретный ответ. Формулы урона, баланс, слабости и иммунитеты, симулятор — без изменений: меняется контент и его подача.

## Не входит

- Ветвление: следующая реплика босса не зависит от выбранного ответа (иначе вчетверо больше текста и ломается симуляция баланса).
- Новые тактики, изменения статов, событий, концовок.
- Новый арт и звук. Пятая карточка «Ударить» и FINISH HIM остаются как есть, у карточки появляется текст.

## Понятие «обмен» (exchange)

```ts
export type Tactic = Exclude<MoveId, 'strike'>;            // 'agree' | 'data' | 'blame' | 'joke'
export interface Reply { text: string; reaction: string }   // ответ героя и реакция босса на него
export interface Exchange { prompt: string; replies: Record<Tactic, Reply> }

export interface Boss {
  // …как раньше: id, name, title, patience, attack, weakness, immunity, final, sprites, portraits
  exchanges: Exchange[];                        // ровно EXCHANGE_COUNT (8); exchanges[0] — открывающая реплика (бывший intro)
  strikeText?: string;                          // текст пятой карточки (≤ 60); обязателен у final, запрещён у остальных
  lines: { special: string[]; defeated: string[] };   // hit, immune и intro удалены
}
```

Порядок обменов в бою: 0, 1, 2, 3, 4, 5, 6, 7, затем по кругу 5, 6, 7, 5, … Константы `EXCHANGE_COUNT = 8` и `LOOP_TAIL = 3` экспортируются из `battle.ts`; валидатор берёт их оттуда же (один источник). `nextExchange(n, i) = i + 1 < n ? i + 1 : Math.max(0, n - LOOP_TAIL)`. Обмены 0–4 — сюжетная дуга босса, 5–7 — «давление», написаны так, чтобы читаться в любом порядке и после любого из соседей. Повторный бой после поражения начинается с обмена 0: повтор допускается, аналог `repeatText` для боёв не вводим (YAGNI). Восемь обменов — сознательно больше, чем видит средний бой (3–9 ходов): хвост нужен для затянувшихся боёв и реваншей.

## Изменения в `battle.ts`

```ts
interface BattleState {
  // …как раньше
  exchange: number;   // индекс обмена, чья реплика на экране и чьи ответы лежат на карточках; createBattle → 0
}
interface TurnResult {  // без текстов: правила не зависят от копирайта, тексты достаёт choreo.ts по индексам
  battle: BattleState;
  outcome: 'continue' | 'win' | 'lose' | 'fatality';
  player: { move: MoveId; damage: number; weakness: boolean; immune: boolean };
  boss: { damage: number; special: boolean; lineIndex: number } | null;
}
```

- `player.lineIndex` удалён вместе со своим вызовом `rng`. За ход `rng` вызывается ровно два раза и всегда: спецприём, затем индекс реплики `special` (берётся даже если спецприёма нет — так поток детерминирован и не зависит от исхода броска).
- `battle.exchange` в результате — уже следующий обмен: `nextExchange(boss.exchanges.length, prev.exchange)`. Обмен, на который игрок отвечал, — `prev.exchange`; хореография получает `prev` и так.
- **Поток случайных чисел сдвигается** (было три вызова за ход): симуляция `npx tsx tools/simulate.ts 1000` и `test/balance.test.ts` (seed 42, 300 боёв) дадут другие числа. Этап 1 обязан перезапустить симуляцию и подтвердить таблицу баланса; если окна (поглощённый урон 60–90, доли повышений, 3–9 ходов) уходят в красное — сначала пересмотреть окно/seed в тесте, и только потом трогать терпение/атаку боссов. Ожидание: сдвиг в пределах шума 300 боёв.
- `pickIndex` остаётся (один вызов). Хелпер `exchangeAt(boss, i)` в `choreo.ts` берёт `exchanges[Math.min(i, length - 1)]` — под `noUncheckedIndexedAccess` без `!`.

## Хореография хода (`choreo.ts`)

Шаг `line` получает режим: `{ t: 'line'; text: string; style: 'bubble' | 'center'; append?: boolean }`. Тексты `choreo.ts` берёт сам: реакция — `exchangeAt(boss, prev.exchange).replies[move].reaction`, реплика — `exchangeAt(boss, r.battle.exchange).prompt`.

```
intro:        ROUND 1 → wait 900 → line(exchanges[0].prompt) → wait 1400 → FIGHT! → wait 700
ход игрока:   clearSpeech (контроллер) → поза attack → выпад → удар/иммунитет → цифра урона → полоска
              → line(reaction)            ← новый пузырь (append: false)
              → wait 900                  ← было 500: реакцию надо успеть увидеть до выпада босса
              → возврат героя
ответ босса:  [спецприём: dim → line(special, center) → wait 900 → flash → dim 0]
              → поза attack → выпад → удар по герою → цифра → полоска → wait 400 → возврат босса
              → line(prompt, append: true) ← дописывается к реакции; висит, пока игрок думает
              → [FINISH HIM: баннер + голос + звук + wait 900] — строго после append
победа:       поза defeated → slow-mo → line(defeated[0]) (append: false) → баннер → конфетти
поражение:    реакция на ответ героя показана, как в обычном ходе; append нет; пузырь остаётся
              под баннером PERFORMANCE REVIEW и сереет вместе со сценой
fatality:     без реплик, как раньше
```

Итог хода на экране: один пузырь «реакция на прошлый ответ + новая реплика», под ним четыре карточки-ответа.

**Таймер.** Счётчик 99 (`scene.startTimer`) на фазе `awaitInput` ставится на паузу и идёт только во время анимаций: `scene.pauseTimer()` / `scene.resumeTimer()` (gsap `pause()`/`resume()` у твина таймера). Иначе он доходит до нуля, пока игрок читает, и выглядит сломанным. Файлы: `render/scene.ts`, `screens/battle.ts`.

**Карточки во время интро** не показываются (`.moves` скрыт до первого `awaitInput`): игрок не должен читать ответы раньше вопроса.

## Пузырь (`effects.ts`)

Константы рядом с `W`/`H`: `BUBBLE_RIGHT_GAP = 60`, `BUBBLE_BOTTOM = 300`, `BUBBLE_WRAP = 380`, `BUBBLE_TOP_MIN = 100`.

- Пузырь `bubble` стоит **в просвете между бойцами**, растёт вниз от HUD: центр по x на `BUBBLE_CENTER_X = 612`, верх на `BUBBLE_TOP = 100`. Замер по idle-спрайтам (700×900 → высота 520): герой занимает x ≤ 450, босс x ≥ 775 (Шан Цзун самый широкий, голова от 787), головы на y 128–275, HUD до ~75. Поэтому коробка не шире 318 (`BUBBLE_WRAP = 290` + 2×14) и не закрывает лиц ни при каком тексте; хвостик указывает вправо на лицо босса (~80 px ниже верха коробки). Худший случай текста (реакция 75 + пустая строка + реплика 110 при ~30 знаках в строке) — 8 строк × 24 px + 28 px ≈ 220 px. Страховка: если высота больше `BUBBLE_MAX_BOTTOM − BUBBLE_TOP` (500 px), шрифт уменьшается до 17 px. Первая версия (справа от центра, правый край на `boss.x − 60`, низ на 300) закрывала лицо босса — исправлено по плейтесту.
- Один пузырь — один `Container` с меткой `label = 'speech'`, внутри ровно один `Text` (`align: 'left'`, `wordWrap`, `wordWrapWidth: BUBBLE_WRAP`) и одна `Graphics` коробка с хвостиком-треугольником вправо, к боссу. Позиция считается от размеров текста: `x = BUBBLE_CENTER_X`, `y = BUBBLE_TOP + h/2` при `anchor 0.5`.
- `append: true`: найти пузырь по метке; если его нет — вести себя как обычный `bubble`. Иначе `text.text = prev + '\n\n' + next`, `box.clear()` и перерисовка коробки и хвостика по новым `width/height`, пересчёт позиции. Без `clearSpeech`, без анимации alpha.
- `append: false` (обычный `bubble`): предыдущий пузырь уничтожается **мгновенно** (не fade — иначе две коробки лежат друг на друге), новый появляется за 0.2 с.
- `clearSpeech(scene)` (уже есть) остаётся для контроллера: гасит пузырь за 0.25 с в момент хода игрока.
- `center` не меняется. Всё, что создаёт твины, ожидаемые контроллером, идёт через `settle`; пузырь ничего не ждёт, но его твин появления регистрируется через `scene.track`, чтобы `unmount` его убил.

## Карточки (`screens/battle.ts`, `styles/battle.css`)

```html
<button class="move-card">
  <span class="move-key">1</span>
  <span class="move-text">Слабых сторон нет. Есть полное согласие с политикой компании.</span>
  <span class="move-meta">Согласиться · ≈17</span>
</button>
```

- `renderMoves()` строит карточку через `createElement`/`append` и `textContent` (сейчас там `innerHTML` — переписать). Тексты ответов — из `exchangeAt(boss, battle.exchange).replies[move.id].text`; у `strike` — `boss.strikeText ?? move.name`.
- Классы `.move-name`/`.move-stat` заменяются на `.move-text`/`.move-meta` в CSS и разметке.
- Текст ответа — главный: `font-size: clamp(11px, 1.15vw, 15px)`, `line-height: 1.3`, `overflow-wrap: anywhere`, `min-height: 3.9em` (три строки — карточки одной высоты и без скачков между ходами), `overflow: hidden`. При пяти колонках на 1280 px внутренняя ширина ≈ 228 px ≈ 30 знаков в строке: лимит ответа 80 знаков — три строки. Подпись `move-meta` мелкая, серая: название тактики и ожидаемый урон (у «Ударить» — только название). Тултип `title` — прежний `move.hint`.
- Порядок карточек фиксирован и совпадает с клавишами: 1 согласие, 2 данные, 3 стрелки, 4 шутка, 5 удар (только финал). Обработчик клавиш 1–5 не меняется.
- Пятая карточка у финального босса показывает `boss.strikeText` и до `finishHim` задизейблена с прежним тултипом.
- Ниже 1024 px кадр масштабируется вместе с карточками; текст на 11 px остаётся в трёх строках при `overflow: hidden` — переполнение обрезается, а не ломает сетку.

## Правила для сценаристов

Объём: 6 боссов × 8 обменов × (1 реплика + 4 ответа + 4 реакции) = 432 реплики плюс `strikeText` у Шао Кана. Существующие `lines.hit` и `lines.immune` — сырьё для реакций: переносить туда, где они подходят к ответу, остальное убрать. `intro` каждого босса — кандидат в `exchanges[0].prompt`. `special` и `defeated` не меняются.

Лимиты (проверяет валидатор): `prompt` ≤ 110 знаков, `reply.text` ≤ 80, `reaction` ≤ 75, `strikeText` ≤ 60, ничего пустого. Лимиты выведены из геометрии пузыря и карточек выше — не поднимать без пересчёта.

Содержание:

- Реплика босса — вопрос, требование или выпад, на который естественно отвечать четырьмя способами. Обмены 5–7 не ссылаются на «первый/последний вопрос» и на порядок.
- Четыре ответа узнаются как тактики и без подписи: согласие — лесть/подчинение; данные — цифра, факт, график; стрелки — виноват кто-то другой (конкретный коллега или отдел); шутка — панчлайн. Ответ не может быть смесью двух тактик.
- Реакция на слабость показывает, что босс задет (сбился, записал, отступил); на иммунитет — отмахнулся с презрением, как нынешние `immune`; нейтральная — принял к сведению и двигается дальше. Реакция не называет тактику словами «вы согласились / пошутили», а отвечает по смыслу.
- Герой без пола: в ответах героя нет прошедшего времени от первого лица и прилагательных о себе («я согласен» → «согласие полное», «я сделал» → «сделано»). Герой обращается ко всем боссам на «вы» (в событиях герой никому не «тыкает»; Барака сам говорит герою «ты» — это асимметрия тимлида и джуна, её сохранить).
- Голоса боссов и занятые формулы — по хендофф-заметкам `docs/superpowers/plans/README.md` (разделы «Этап N выполнен»). Сквозные шутки подхватывать, не повторять дословно; ни одна реплика не повторяется у двух боссов.
- Слово «синергия» — только там, где оно уже сюжетно закреплено (Барака запрещает, Шанг Цунг любит, Шао Кан увольняет).
- Ответы не меняют статы и флаги: бой — только урон.
- Шао Кан: `strikeText` — действие героя, одна строка ≤ 60 знаков, в кавычках-«ёлочках» не оформляется (это не реплика).
- Шао Кан: у финальной ступени нет событий, поэтому `test/content.test.ts` ищет намёки на слабость и иммунитет в `exchanges[0].prompt` — там обязаны быть слова из `HINT_WORDS` для `agree` (соглас/лоял/кива) и `data` (данн/цифр/график/отчёт). Нынешнее intro этому удовлетворяет.

## Валидатор (`content/schema.ts`)

- `exchanges.length === EXCHANGE_COUNT` (импорт из `battle.ts`); у каждого обмена ровно четыре ответа с ключами `agree, data, blame, joke`.
- Лимиты длины и непустота `prompt`, `text`, `reaction`; `strikeText` ≤ 60.
- `strikeText` обязателен и непуст при `final`, отсутствует у остальных.
- Глобальная уникальность всех `prompt`/`text`/`reaction` по всем боссам (через имеющийся `unique()`): правило «ни одна реплика не повторяется у двух боссов» иначе не проверить.
- `lines.special` и `lines.defeated` непусты (как раньше).

## Тесты

- `test/fixtures.ts`: босс с восемью короткими обменами вместо `intro/hit/immune`.
- `test/battle.test.ts`: `exchange` растёт 0→1→…→7→5→6→7→5; `nextExchange` клампит (`n = 2` → 0); при `win` `boss === null`; порядок `rng` пересчитан (два вызова за ход, всегда); у `player` нет `lineIndex`.
- `test/choreo.test.ts`: интро содержит `exchanges[0].prompt` без `append`; ход содержит `line(reaction)` (текст из `prev.exchange`) до возврата героя и `line(prompt, append: true)` (текст из `r.battle.exchange`) после атаки босса и только при `continue`; `append` идёт раньше баннера FINISH HIM; при `lose` реакция есть, `append` нет; спецприём — `center` без `append`; победа — `defeated[0]` без `append`; `exchangeAt` клампит индекс.
- `test/content.test.ts`: подсказки слабости/иммунитета ищутся, как раньше, в последнем событии; ссылка на `boss.intro` заменяется на `exchanges[0].prompt`.
- `test/schema.test.ts`: новые ошибки валидатора (7 обменов, лишний ключ ответа, длина 111/81/76, `strikeText` у не-финала и его отсутствие у финала, дубль реплики у двух боссов).
- Симуляция баланса `tools/simulate.ts` и `test/balance.test.ts`: тексты на урон не влияют, но поток `rng` сдвинут — перезапустить и подтвердить (см. раздел про `battle.ts`).

## Плейтест

Playwright: пузырь после интро висит до хода; карточек во время интро нет; после хода виден пузырь «реакция + новая реплика» и карточки с ответами; для самого длинного обмена каждого босса проверить через `evaluate` инвариант «верх пузыря ≥ 100 px» и глазами — что он не закрывает лицо босса (скриншоты шести боссов); таймер стоит на `awaitInput`; Шао Кан — пятая карточка с `strikeText`; консоль без ошибок. Полное прохождение до повышения.
